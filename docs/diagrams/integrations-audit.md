# Platform and migration diagram audit

This audit covers every Angular and React platform/migration page individually: 36 pages, 30 add decisions and 6 deliberate no-add decisions. Existing code, demos, backend panels, links and historical migration examples remain in place. Opening concept placeholders are replaced by the diagrams named below; no page in this scope retains an old placeholder.

Diagrams begin with a reusable boundary before moving into specific routes or reference applications. Direct provider adapters, hosted .NET/LangGraph agents, and TypeSafe JSON decisions have separate contracts. React and Angular Threadplane migrations deliberately use different ownership diagrams.

## Database and guarantee checks

The recording-plan ERD depicts only the actual `hashbrown_production.application_plans` and `application_receipts` DDL in `www/examples/quickstart/server/production/storage.ts`. The receipt's `(thread_id, operation_revision)` is the composite primary key. Its `thread_id` is the declared foreign key to `application_plans(thread_id)`. `owner_id` is a required column, not a declared foreign key. A plan has zero or many receipts by schema; this reference's acceptance function writes only revision zero. The caption and equivalent text distinguish schema cardinality from this bounded behavior.

Installed `@b4run/postgres-storage` 0.15.7 was inspected in `node_modules/@b4run/postgres-storage/dist/{schema,checkpointer,run-admission,interrupt-grants}.js`. Its runtime threads/checkpoints/writes/grants are separate tables; the checkpointer uses composite thread/namespace/checkpoint identity. No database foreign key from these tables to the application's plan row was invented. The opening b4.run figure is explicitly a conceptual responsibility map, not a runtime-table ERD. The guide's pinned 0.15.5 historical reference was preserved; the application ERD relies on repository-owned DDL rather than assuming an installed package version reproduces that historical runtime schema.

Neither storage nor restore confers execution authority. Recovery and local restoration are read/install operations. Explicit approval, required grants, ownership checks and admission remain part of the run path. The application transaction protects this database result; diagrams do not promise exactly-once external effects, generic SDK persistence, automatic retries, or cold restoration of unresolved .NET mixed browser work.

## Validation

The 13 new definitions have source-evidence comments. They use the existing static diagram renderer and server-side catalogue, with no new dependency or SDK changes. Each diagram has a teaching title, caption and equivalent text. Geometry and ID references are checked with `validateDiagram`; Markdown additions are checked against definitions and the existing shared `request-boundary`. ERD nodes use 440-unit widths for real column names. Package-wide build/test/lint and browser layout checks are coordinated by the parent task to avoid concurrent broad runs.

Voice reference: Brian Love's 2020 Angular Transfer State article (`~/repos/brianflove/src/content/posts/2020-06-05-angular-transfer-state.md`): concrete problem first, explain ownership, then walk into the implementation. New captions use that direct instructional voice without rewriting historical prose.
