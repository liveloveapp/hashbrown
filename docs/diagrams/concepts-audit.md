# Concept diagram audit

Audited all 30 Angular and React concept pages. Each has an existing generic diagram; each benefits from a more precise diagram before its first application example. The replacement teaches the general concept, then the existing code and workbench apply it. No second diagram is added to the workbench. All existing bookmarks, code, video, panels, links, and section order are preserved.

**Decision vocabulary:** add means replace the generic `hb-concept-diagram` with a purpose-built `hb-diagram`; retain means keep a useful existing visual; no-add means a new diagram would not improve the explanation. All 30 decisions below are add because these particular generic flows hide distinct boundaries or relationships. This is a page-by-page teaching decision, not a requirement that every docs page receive a diagram.

Source checks distinguish browser tool handlers from server provider calls; display-only activities from model context; preview values from completion; approval from execution; and application storage from an agent checkpoint. The runtime diagram includes an optional host call, while the introductory fixed-script example exposes no host functions. The shared-state diagram describes the successful commit path; its text alternative also explains rollback on failure. Diagrams describe contracts and information flow, not durable storage guarantees.
