# Generic Pydantic AI compatibility

Status: user approved the limited adapter and directed a generic protocol boundary on 2026-10-31. This addendum supersedes the earlier proposal to implement B4's tool-step contract in Python. File search remains deferred.

## Purpose and boundaries

Pydantic AI already implements AG-UI frontend tool registration, deferred execution, continuation and approval resumes. Reuse those public APIs unchanged. The optional `hashbrown-pydantic-ai` distribution only translates demonstrated protocol compatibility gaps. Applications supply their existing agent, tools and deployment; no application-specific translator, executor, storage or orchestration service is required.

The adapter must not import, emit, synthesize or depend on B4 contracts. Hashbrown must accept generic tool outcomes independently of its existing backwards-compatible B4 integration. Do not rename or copy the B4 step schema into this adapter. Existing provider/B4 conformance remains valid.

## Wire and consumer model

Use standard AG-UI TOOL_CALL_* lifecycle, STEP_STARTED/STEP_FINISHED, ACTIVITY_SNAPSHOT/ACTIVITY_DELTA, state, interrupt and message events. Do not wrap standard actions, steps or progress in a new vendor protocol. Only test or augment a capability when native execution demonstrates a gap.

The installed AG-UI 1.0 tool-result schema has metadata but no typed per-tool outcome (ToolMessage has only an error string). Define a small optional `metadata["hashbrown.tool"] = {v: 1, outcome: "success" | "failure" | "denied" | "cancelled" | "interrupted" | "retried", error?: {message: string}}` extension on tool RESULT and canonical ToolMessage. This is a terminal outcome record, not an alternative lifecycle or rich step contract. A failure requires a nonempty message. Unknown versions/outcomes or malformed payloads are ignored. Preserve unrelated metadata and native continuity events. Do not use the AG-UI-reserved metadata namespace.

Core reads this neutral outcome into its generic internal/public tool model, without converting it to a B4 step. Result content remains the real native content. Failure produces rejected result/error; denial and cancellation settle display and survive canonical JSON restore and next-request serialization. A duplicate successful result must not erase a previous failure/denial/cancellation; failure has precedence. Existing B4 interpretation stays a separate compatibility path. A registered matching client tool retains ownership; metadata must not manufacture provider ownership.

Python reads actual native ToolReturnPart outcomes through public event-stream handlers: success -> success; failed -> failure; denied -> denied; interrupted -> interrupted; retried -> retried. An interrupted return alone does not establish cancellation (it can also represent crash/history repair). Only a real RunCancelled observed through the public transform_stream boundary establishes cancelled for interrupted results from that run. Native history alone retains interrupted unless explicit cancellation provenance is available. Interrupted and retried settle the current call with explicit public interrupted/retried outcomes and corresponding labels; they must never group as successes. A later genuine settlement may replace interrupted/retried, but failure always wins and denied/cancelled cannot be overwritten by success. Between denied and cancelled, retain the first terminal bad outcome. Valid neutral metadata takes precedence over legacy B4 display metadata; a canonical nonempty error still establishes failure. Invalid neutral metadata does not shadow valid legacy support. Typed failure with empty detail uses the generic message "Tool execution failed". Investigate validation outcomes with real executions and retain their native continuation semantics; do not guess errors from result prose. Error content can supply readable detail only after a typed failure establishes classification. Augment native dump_messages with the same terminal metadata by matching superclass-produced messages to actual native call IDs, including native builtin ID translation; do not import private ID-prefix helpers. Preserve native load_messages sanitization; never promote client-supplied metadata to trusted backend execution state.

A demonstrated consumer gap also requires generic terminal-error retention: after an accepted server RUN_ERROR, retain only completed server-owned call/result pairs in canonical history. Keep the original run error; do not dispatch a successful generation or client tool execution. Exclude partial assistant text, structured UI, pending client calls and uncommitted state. Guard retention with the generation/attempt ownership boundary and preserve existing call/subagent identity. Transport EOF, protocol errors, retired attempts and retry rollback retain their existing transactional behavior. This behavior is framework-neutral and does not require outcome metadata from any particular producer.

## API and packaging

Expose a public AGUIAdapter subclass and corresponding AGUIEventStream subclass. Consumers substitute the adapter at their existing `dispatch_request` boundary; the adapter inherits native frontend-tool handling. Export only necessary types/helpers, with documented contracts. Use public hooks and superclass behavior; no monkeypatches/private imports. The package does not add agent options, tool executors, persistence or artificial activities.

Dependencies were explicitly approved: pydantic-ai-slim[ag-ui]>=2.64,<3, ag-ui-protocol>=1,<2, Starlette>=0.46.2,<2; uv_build==0.11.3. Qualification keeps exact existing pins. Build and install a wheel in isolation, then run real protocol qualification against the installed distribution. Publishing is outside this PR.

## Qualification

Keep the native asgi-baseline record and retained evidence unchanged. Add a separately versioned recipe profile, visibly labeled passed with recipe only for stages actually executed. Real deterministic models may drive scenarios, but tools, native adapter, HTTP, prepared root store, canonical serialization and both browser consumers must execute normally. No edited trace can stand in for producer output.

Required acceptance: real server callback success/failure; cancellation with no late side effect; denied approval resume and approved client round trip; native history continuity; canonical JSON restore and next request; collision rejection unchanged; standard activities/steps/state pass through without B4 metadata; malformed/unknown metadata; duplicate settlements; isolated wheel installation. Broader untested capabilities are probed using native mechanisms and reported individually. Do not claim backend restart recovery from client JSON restore, trusted UI from arbitrary JSON, or attributed subagents from merely executing a child. Preserve clear not-tested or demonstrated-gap entries when no evidence exists.

Affected PR gates and weekly compatibility checks must include package source/build inputs and the recipe test host without adding runtime dependencies to JS packages. Public compatibility documentation must distinguish native baseline from recipe results.
