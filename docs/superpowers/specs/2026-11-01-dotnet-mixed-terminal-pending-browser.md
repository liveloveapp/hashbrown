# Task 3 refinement: mixed native interrupt pending browser IDs

Status: reviewed and implemented Task 3 refinement, unreleased. Its scoped server/core transport qualification is recorded in [the checkpoint](../research/2026-11-01-dotnet-pending-browser-bridge-qualification.md). Published npm 0.8.3 and NuGet preview1 remain immutable.

## Observed incompatibility

The pinned native public adapter emits a genuine `RUN_FINISHED` interrupt containing only `outcome.type` and genuine protected `outcome.interrupts`. Its ordinary browser siblings remain unanswered in the durably captured canonical public history. The current core reducer already interprets `outcome.pendingToolCallIds` as additional calls kept open, but its absence makes `settleToolSteps` attach server/cancelled metadata to those browser siblings. Independent exact native projection/core reducer comparison exposed this discrepancy after rich grouped-call projection became available. Cancelling the canonical browser call or ignoring metadata in that comparison would misrepresent the pending recovery contract.

## Proposed narrow exception to terminal byte preservation

At the native endpoint's existing held public terminal boundary, append `outcome.pendingToolCallIds` only for a validated mixed native interrupt with genuine currently unanswered browser siblings. This is an application-owned AGUI transport adaptation, never a provider request/output rewrite, a fabricated browser approval, or native-history restoration. Preserve every protected interrupt unchanged. The reducer already consumes this field, but the public transport currently discards it: `ValidatedRunFinishedOutcome` omits it and `ag-ui-run-driver.ts` reconstructs interrupt outcomes with only type and interrupts. Include a narrow core transport preservation slice; no reducer behavior changes.

The original guarantee that every terminal is released byte-for-byte needs one explicit exception for this characterized mixed interrupt. All absent/nonmixed/browser-only/no-pending-browser cases retain exact original terminal bytes. Ordinary nonterminal frames always remain byte-identical. The adapted mixed terminal must preserve all other parsed terminal fields and protected interrupt values; a deterministic valid SSE encoding may change terminal JSON formatting. This exception requires review and a repository spec/plan amendment before implementation.

## Placement and authority

Implement inside `NativeSessionProjection.Complete`, after genuine terminal validation, full bounded raw/canonical obligations, and complete current pending witness agreement have succeeded, and before `NativeMafSessionStore.SaveSessionAsync` reads `Result` or the terminal can be released. No provider, session API, effect fence, or browser handler is called by adaptation.

Derive pending browser IDs in original public message/call order from the completed canonical fold. Require that each is still unanswered, names an admitted browser declaration, and exactly matches an independent current pending browser witness from `NativeSessionContext.ProjectionApprovals`: ID, name, arguments, and original native content position/identity where present. For initial publication there is no preexisting bound public location: establish one unique canonical location through the completed strict fold and preserve it for the ordinary journal binding. Historical bound positions, when present, must agree; never invent native identities or demand an initial public binding before projection creates it. Require set equality with all current genuine pending browser witnesses; partial sets, missing/foreign/duplicate witnesses, already answered calls, changed names/arguments/positions, and browser/protected classification mismatches make the projection unavailable. The canonical folded text alone is never witness authority. A request cannot manufacture this list using forwarded properties, arbitrary metadata, or generic decisions.

For this initial-publication path, the current context contains genuinely observed nonconfirmation browser request bindings and protected approval requests before native public projection. Browser-only ordinary declarations need no synthetic protected batch and receive no adapted interrupt. If a characterized mixed shape lacks the independent genuine browser witness, fail closed; do not infer a request binding from transcript strings.

Continue requiring the original incoming native interrupt outcome's exact supported `type` + `interrupts` shape. Reject an unsolicited incoming `pendingToolCallIds` field rather than accepting it as authority. The adapter adds the field only after those validations and does not feed its own adapted representation back into native validation.

## Required existing core transport preservation

Extend internal `ValidatedRunFinishedOutcome` interrupt values with an optional readonly `pendingToolCallIds` array. Validate/clone/freeze the optional array independently from interrupts: array of unique nonblank strings, subject to the existing public transport frame/request byte bounds. Do not introduce an arbitrary generic provider count or ID-byte limit: 256 is the native server default MaximumCalls, which is configurable, and native identity byte limits do not automatically apply to other core providers. Reject sparse arrays, nonstrings, duplicates and unsupported shapes. An omitted property stays omitted; an explicitly empty array may remain empty, subject to established internal JSON data validation conventions. The field records kept-open transport observations and grants no tool, approval, browser execution or recovery authority.

Have `ag-ui-run-driver.ts` preserve this owned validated optional array when it rebuilds the interrupt terminal sent to `onEvent`. Preserve the existing validated interrupt array and return type. Do not use the field as a decision/interrupt, add reducer semantics, create browser approval responses, or change client cold recovery state here. The server independently binds the exact complete ID set; the driver must not infer names/arguments or authority from it. If full call-set membership validation at the driver is desired, review it explicitly before implementation because the current driver has no such model-call registry.

Add real public driver/runtime tests that feed the enriched terminal through the actual transport validator and reconstructed callback event, then into the existing reducer. Require the original browser calls remain free of cancelled/server metadata; genuine protected interrupts remain intact; malformed arrays fail as protocol errors; original arrays cannot mutate emitted state; absent-field existing terminal cases remain unchanged. Merely invoking the reducer directly on a fabricated enriched terminal cannot qualify this slice.
