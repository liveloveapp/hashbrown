## Design

Add three recorded examples through actual React and Angular clients: an authenticated text endpoint, server-stored text threads, and QuickJS execution through explicitly exposed functions. Reuse installed Express, AG-UI, Vite, Playwright, and ffmpeg dependencies. New files live beside the checked Quickstart examples and compile under its existing strict target. No package API changes.

The endpoint is a composable Express app with injected identity verification, run admission/rate control, thread repository, and provider stream. Every thread read/write/run verifies identity and ownership. Every POST/PUT requires an Origin header matching the configured application origin; the local session cookie is HttpOnly and SameSite=Strict. No permissive CORS is enabled. The server bounds bodies and text histories and constructs a fresh provider input: pinned system instructions, no browser tools or response schema, explicit state/context/forwarded-props policy, model and output cap set in the production adapter. SSE headers are sent only after validation; errors after streaming are terminal AG-UI events. Abort provider work on disconnect. Thread writes use an expected version and an atomic repository compare-and-swap, returning 409 on conflict. Invalid, unauthorized, oversized, and conflicting requests must never call the provider or overwrite saved data. The browser transcript remains untrusted content, not evidence for privileged actions.

The reference repository is in memory, explicitly for local demonstrations. Production guidance explains authenticated sessions, atomic database updates, distributed admission limits, retention, no-store caching, and deployment. The recorder uses opaque server-issued local fixture sessions, not a deployed login service. The example is a checked application pattern with replaceable integration points, not a claim of a complete hosted identity/database platform.

Both SDK clients load before creating a chat, recreate on selection, serialize completed text saves, show load/save/conflict errors, support explicit conflict reload, and preserve current messages after a failed save. Switching must not allow a stale load/save to replace the newly selected thread. No secrets are embedded in the client. Thread storage preserves completed text only and does not restore canonical provider metadata, generated UI/tools, shared state, or paused interrupt ownership. A thread ID never loads or authorizes history by itself.

The runtime example executes real QuickJS, shows the submitted script and returned result, and exposes a read-only basket function with explicit host-side input validation. Demonstrate normal calculation and unavailable browser globals/error recovery. Explain that exposed handlers execute in the host application while QuickJS bridges those calls; they remain privileged capabilities that need their own authorization. Explain the actual result/error wrapper, per-run context lifetime, timeout/abort limits, and the optional javascript tool integration. Runtime function schemas describe the model-facing contract; the current QuickJS bridge does not automatically validate their arguments or results, so the host handler validates explicitly. Verify claims against current source rather than repeating old broad sandbox guarantees.
