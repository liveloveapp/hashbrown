# Completion Native Thread Qualification

Status: implemented and independently reviewed. Local receipt tests, build, complete harness tests, and lint pass. Fresh source-candidate isolation and full browser execution remain pending; no full-matrix success is claimed.

## Decision and scope

Completion inputs replace history. NativeSessions retain an owned canonical prefix and reject its replacement under the same selector. Qualify both contracts together: after genuine cold settlement and strict Completed restore, completion-family rows must prove the real same-thread replacement is refused, then use the existing explicit New thread control for a successful fresh prediction. Chat-family rows continue appending one user turn to the same retained thread.

This applies to React and Angular completion, structured-completion and UI-completion across all eight compositions. It changes no manifest IDs, applicability, or count: all 372 cases remain required, with workers1/retries0 and exact reporter completeness. It adds no SDK API, dependency, implicit identity rewrite, native admission relaxation or published example change.

Actual attempt14 retained case42 shows Completed R8 restored successfully, then a same-thread replacement request containing only system plus new user received upstream/delivered400 with an empty entity before any additional model request. Its ordinary-answer poll timed out. The packet proves this mismatch; it does not prove the proposed fresh-thread continuation yet.

## Public semantics and explicit action

React useCompletionInput and Angular connectCompletionInput submit the latest input through setMessages([one user]). Structured/UI completion share that lifecycle. Existing public options accept threadId (reactive in Angular); the completion result does not expose a newThread/reset method. NativeSessionHistory.Admits admits a completed retained prefix plus exactly one user, and must keep rejecting replacement.

The existing candidate New thread button invalidates the read guard and navigates the same owned page/config with a fresh opaque threadId. It remounts the actual public facade without automatic generation. This explicit fixture action supplies the public threadId option; it is not a newly invented SDK command. A new input under a stateful NativeSession needs a fresh selector when it replaces prior history. Stateless completion behavior is unchanged.

Rejected alternatives: changing completion to append would change one-shot prediction semantics; accepting arbitrary replacement would weaken stored-history authority; silently rewriting request identities or manually dispatching transport would fail public-facade qualification; omitting ordinary completion or removing cases would reduce acceptance scope.
