**Magic Text:** send an explicit request through the checked text-chat endpoint. **Predictive suggestions:** use the actual structured-completion APIs to suggest packing-list items after an explicit user context change. A bounded catalog of item IDs, plain reasons, and an application-owned request/context ID tie suggestions to the current snapshot. Show completed valid results only. Accept and Dismiss are explicit. Accept revalidates against the current context and item list; filter duplicate, applied and dismissed IDs; reject the whole response when any ID or bounded reason is invalid. This conservative policy avoids partially offering a malformed proposal. A context change immediately invalidates old output, including the debounce window. Failed, cancelled, truncated or late results cannot mutate the list. Accepted/dismissed AI suggestions must not trigger another completion by themselves. Use an empty suggestions array as a valid outcome. Do not display a model-generated confidence number as a calibrated probability.

**UI selection:** use candidates mode in the actual UI-decision APIs to choose an app-owned summary or item-list component. The application supplies all props and data. The model chooses only the candidate ID. Explain null input, loading, errors and low-confidence results with an explicit manual fallback. A checked TypeSafe decision route keeps credentials/model on the server and pins questions with the same candidate definitions/order. Required existing adapter is already in this monorepo; add no dependency declarations. Browser examples use /api/decide; /api/chat remains a separate feature endpoint. Verify both views, low confidence, errors, rapid replacement/late old response, manual fallback and recovery. Summarize chat mode separately with links and accurate fallback/restoration/authorization limits; do not present an incomplete chat example as the checked candidate implementation.
