# Task 3 refinement: two authority modes for native provider input

Status: reviewed and implemented Task 3 refinement, unreleased. Server-bridge qualification is recorded in [the checkpoint](../research/2026-11-01-dotnet-pending-browser-bridge-qualification.md). The two authority modes below are the only exceptions to the original projection restrictions. Published artifacts remain immutable.

## Evidence and decision

The actual production route matrix proves two different failures. FICC regroups several protected requests at one last anchor and sorts rejected calls before approved calls; some resulting Chat requests have separate assistant-call messages before any outputs. A second ordinary fresh-agent continuation reproduces canonical later assistant text before existing tool results, violating provider grammar again. The independent 288-case public-API research and [pinned upstream source](https://raw.githubusercontent.com/dotnet/extensions/02107c65bab30aad9e35b5133ed643eaa77bccd8/src/Libraries/Microsoft.Extensions.AI/ChatCompletion/FunctionInvokingChatClient.cs) corroborate the first constraint. The separate 34-case result-codec characterization and ten additional non-default JSON-layout cases establish actual-return tag/raw/null behavior and the distinct provider formatting step; see the [research record](../research/2026-11-01-dotnet-provider-input-projection-research.md). HTTP fixture success is not vendor acceptance; strict wire validators remain required.

Retain genuine current approval reconstruction and native execution. Add two distinct, pure, independently bounded provider-input projections. A pairs only fully completed journal-accepted historical calls before FICC. B pairs only the fixed admitted current recovery batch after genuine FICC execution/settlement and before the actual provider. Share cloning/pair-planning utilities if helpful, but never combine historical accepted results and current invocation authority into one undifferentiated map. No broad transcript repair, provider OUTPUT rewriting, opaque session surgery, new durable flags, dependencies or DDL.

## A: closed accepted history

Authority comes from the exact saved public snapshot returned by successful authenticated journal acquisition and its unchanged accepted incoming prefix. Prevalidate the converted typed input against that source; arbitrary caller transcript is not independent authority. Identify and exclude all currently unsettled browser/native IDs and the actual owned approval batch. A must not treat a newly approved native call without a real result as historical.

Each targeted historical call must have exactly one matching accepted canonical tool result. Verify unique IDs, exact names/arguments/result strings/roles and supported original locations. Reject old unresolved calls, duplicate/foreign/missing results, ambiguous regions or unsupported metadata before entering inner native execution/FICC. Existing raw/bound/config/ownership checks still precede native session preparation. Typed validation occurs at Restore before InnerAgent.Run; it does not claim to precede already fenced public session deserialization.

Build independent ordinary FunctionCallContent/FunctionResultContent pairs in original canonical call order, before later unrelated text. Preserve exact text values and relative order of unrelated system/user/assistant content. Public canonical message IDs, positions, history/state/tools/schema/config and native opaque bytes remain unchanged. Only native/provider clone IDs/grouping may differ, with deterministic collision-free identities. No historical ToolApprovalRequestContent/CreateResponse, dispatch or tool coordinator is constructed. A runs on subsequent ordinary generations without a recovery envelope; it must close the actual second-cycle RED.

## B: current owned recovery batch

B applies only when the request has the explicitly admitted recovery envelope, matching lease/generation and complete reservation. Before inner native execution, capture a bounded immutable manifest of the exact original current call IDs/order/arguments/locations/text and the allowed transformed typed layout. Browser values come only from exact admitted canonical result strings. Protected request identities and decisions come only from genuine owned batch evidence. Unknown original typed metadata/content fails before FICC/tool invocation/provider work.

Keep the existing genuine pre-FICC protected ToolApprovalRequestContent/CreateResponse path. Do not add a browser approval, approve a declaration-only function, invoke handlers directly or change native decision sequencing. B operates at HashbrownRequestClient immediately before the inner provider receives messages, after the genuine current results have passed the independent gates below.

Verify the received FICC list has a complete bijection with the current manifest: every current call/result exactly once, exact ID/name/arguments/value, no leftover approval wrappers, no unexplained current artifacts, and only the characterized grouped/split/last-anchor/rejection-first changes. Bind residual text/message metadata to the immutable pre-FICC manifest; global call-set matching alone is insufficient. Unknown/changed current content or metadata fails before the provider request. Rebuild only independent current provider-input clones into original call/result order before later unrelated content, preserving all non-target history and fresh native content.

FICC retains its own list, so B revalidates and projects idempotently on every provider entry in that same request. Never mutate or mark FICC's messages. Fresh model-issued IDs follow ordinary policy and remain outside this fixed batch; collision with original IDs rejects rather than reusing an old result. Additional real model/tool iterations must be tested. No request-local witness survives owner/request disposal.

## Independent result witnesses and codec

The invocation middleware sees the actual function return. For a current approved call, create a bounded independent JSON snapshot of that actual return, then expose it as a witness only after successful durable CompleteDispatch under the same lease/token/generation/call/member lineage. Do not mutate the application return object. Completion state alone is insufficient; a model/raw/outward FunctionResult alone is insufficient.

Use an explicit characterized getter-free codec. Default AIFunctionFactory marshals ordinary returns to JsonElement. Preserve its exact actual-return/outward raw representation, including indentation/escaping, and clone only after checking its actual UTF-8 byte/depth limits; reserialization/minification is not an equivalent actual-return witness. The canonical AG-UI tool-content string preserves that raw JSON, while the pinned SDK normally reindents a typed JsonElement at provider serialization. After authenticating the typed result against its witness, B explicitly emits the exact canonical AG-UI content as the Result STRING of its independent ordinary FunctionResultContent. This prevents further serializer reformatting and makes current and later historical provider outputs identical. Do not change the application value, FICC list, native/public outputs or saved canonical content to achieve this. The public GetRawText accessor materializes that representation once before its byte count can be checked; this draft promises bounded retained witnesses, not an unsupported preallocation memory guarantee for arbitrary application returns. Immutable CLR JSON primitives/null may be supported only with characterized native serialization semantics. A raw CLR string is sent plain, while a JsonElement string is sent as its quoted JSON representation. JsonElement null is the string null; a true null reference (void/Task void/custom marshal null) becomes the pinned native success sentinel Success: Function completed. Keep those distinctions explicit. Do not reflectively serialize arbitrary custom objects, custom MarshalResult values, AIContent or collections to obtain a witness. Refuse unsupported output without invoking extra getters/custom converters. Exact null/void behavior must be characterized against FICC (including any native success sentinel) before accepting it. Aggregate witness bytes/count use applicable configured native/public limits; do not invent generic provider caps.

At the outward native result boundary, verify the actual current protected FunctionResult against that completed actual-return witness and its supported metadata. For declined/cancelled decisions, record a witness only after the existing exact genuine rejection settlement succeeds. Never let a provider lookalike or duplicate overwrite a witness. B requires complete protected witness availability before any provider entry. Browser results remain exact admitted observations, not proof that an external effect did or did not occur.

Unsupported result codec/metadata, changed output, completion refusal, rejection refusal or lease loss after an effect withholds provider/public success and preserves Started/Completed/consumed fences and existing Blocked/UnknownEffect cleanup. It never returns a retryable Ready claim or redispatches the original effect. Snapshot/ownership ordering and no-retry disposition need explicit tests. No transient recovery/normalization/witness data enters public or opaque saved representations.

## Boundaries and compatibility

This is an explicit exception to the old bans on completed historical/provider-input projection. Canonical history remains untouched. Historical approvals/execution, arbitrary retained opaque history normalization, provider output rewriting and inferred authority remain prohibited. A and B have separate authority-bearing entrypoints and data; a shared pure pairing helper cannot grant authority itself.

A's ordinary-cycle serialization behavior is intentional; acquisition and legacy warm approval/browser-result contracts remain unchanged. B stays limited to explicit recovered admission. No public API, package version or dependency change is anticipated. Unsupported native metadata remains fail closed; supported shapes are those characterized and tested. The original application-owned empty native history filters remain intact.
