# Native .NET MAF approvals design — milestone two

Status: design and plan independently approved. The reviewed execution amendment permits implementation in a separate managed worktree from the frozen qualified milestone-one commit. Preserve the first checkout and evidence. No milestone-two PR or integration occurs before milestone-one merged-tree equality and required main/native/docs verification. Rebase only milestone-two changes onto the verified first squash merge. If the foundation changes or qualification fails, stop dependent work and requalify it. Root retains all adoption, build, provider and merge ownership.

## Goal and scope

Allow a genuine pinned MAF `ApprovalRequiredAIFunction` to use Hashbrown's existing generic interrupt controls on the authenticated PostgreSQL-owned native-session route. A complete human decision batch resumes the original native requests. Only approved registered functions may receive a durable dispatch grant. Decline and decision cancellation produce native rejection results with zero dispatch for those calls. At most one registered executor dispatch is guaranteed for an owned call; exactly-once external effects are not.

Reuse milestone one's session key, catalog, native serialization, canonical prefix, owner/lease/CAS, dispatch markers, publication barrier, operator reconciliation and retention. Keep application workflow confirmation/schema-3 checkpoints distinct. Keep published React/Angular SDK 0.8.3 and their replay/recovery guards unchanged. No SDK release, new dependency, package/version update, custom model/tool orchestration, release safeguards, NuGet work, cloud managed identity qualification or reasoning-model support is included.

## Evidence and alternatives

1. **Recommended: public-only native compatibility adapter plus one durable journal.** A narrow outer `DelegatingAIAgent` reconstructs server-owned native request contents in place, maps strictly admitted generic decisions through `original.CreateResponse`, and adjusts public projection only. An upstream-only empty-tools transport clone avoids the pinned AGUI classifier; the original browser declarations are supplied through cloned native run options. Native MAF retains argument binding, approval binding, function invocation and model history. This adds several precise compatibility rules but preserves both existing SDK behavior and effect ownership.
2. **Separate application confirmation workflow.** The existing workflow can express a confirmation, but it would not resume native approval requests or meet the requested native interoperability contract. Keep it available as a separate recipe.
3. **Modify AGUI internals or SDK replay/recovery rules.** This broadens compatibility and release scope and still does not supply durable effect ownership. Reject private-state/reflection access, fabricated native events and relaxed SDK guards.

The evidence is local characterization of the pinned packages, not a guarantee about future upstream releases. The preserved task evidence bundle contains `milestone2-approval-design/research-findings.md`, `verified-evidence.json`, `evidence-assertions-final.log`, and `recovery-research/{findings.md,verified-recovery.json}`; their pinned characterization is summarized below. Earlier failed experiments remain evidence and must not be cited as passes.

Verified feasibility includes five strict native fixture shapes; all six published React/Angular approve/decline/cancel paths with a co-emitted registered browser sibling; exact FIRST resumed model histories; fresh browser calls after the native rejection; and clean subsequent turns. Those six paths produced 24 actual HTTP posts, 24 fake-model invocations and two backend effects, confined to approval. Separate actual reload tests rejected eight pending mixed snapshots, while two native-only approval controls restored fresh local batches and dispatched once. These in-memory probes prove neither durability nor concurrent ownership. Implementation must re-establish their behavior against the journal.

## Canonical invariants

The following are acceptance requirements, not implementation suggestions.

- **I1 — authority:** the complete native key is stable agent + trusted authenticated scope + selector + every ordinal store partition. Compatibility is separately checked for provider/API/endpoint/model, native format and catalog. Run IDs, browser local batch IDs, metadata and caller JSON supply no execution authority.
- **I2 — provenance:** only genuine inner native request contents may create approval/browser bindings. Each protected approval agrees with an actual captured model server descriptor and registered catalog version. Neither caller pending calls nor typed responses synthesized by AGUI can create or approve a descriptor.
- **I3 — uniqueness:** within a selector, native request IDs and call IDs are permanently bound once. Repeated identical observation within the same unconsumed capture may be idempotent; a consumed, settled or retired identity cannot be recaptured. Semantic JSON comparison does not permit name, version, parent, position or role changes.
- **I4 — canonical public prefix:** save the original admitted public configuration/history advanced only by genuine public events. Never save the upstream empty-tools clone. Preserve native parents or the SDK's exact `assistant-{callId}` fallback. A public completed/denied call has exactly one real result and one original call. A hidden captured server descriptor stays private until MAF emits it.
- **I5 — atomic pending publication:** native blob, public prefix, pending protected approval batch, captured browser bypass bindings, pending server descriptors and expected browser-result IDs commit together. Every published native interrupt matches exactly one pending protected request and its public call, and the complete batch matches the genuine terminal. Do not publish an interrupt solely because upstream emitted `RUN_FINISHED`.
- **I6 — whole-batch decision:** validate every member and the exact owned prefix/configuration before consuming any decision. Exactly the published current IDs appear once, order independent. Missing/extra/duplicate/stale/cross-scope/expired/settled IDs fail before model/effect work.
- **I7 — irreversible admission:** one transaction commits `Pending -> DecisionAdmitted` for all members, decision kinds, owner generation and revision. Once committed, even a zero-dispatch failure cannot restore Pending. Retain the consumed fence and block/quarantine any unknown outcome; operator retirement/reconciliation cannot reopen it.
- **I8 — dispatch:** an approval-required function needs a current admitted Approved decision for that exact request/call/catalog/session AND the existing current-owner `Captured -> Started` CAS before calling native `next`. Decision admission itself never grants dispatch. Declined/Cancelled cannot reach Started, including if native code incorrectly attempts invocation.
- **I9 — zero-dispatch settlement:** decline/cancel settle into explicit `Declined`/`Cancelled` invocation states only with the matching admitted decision and genuine native rejection result. Never fake Started/Completed or remove the call fence to satisfy save validation. Approved executions settle through Started/Completed. All terminal call identities remain fenced.
- **I10 — owned publication:** save receipt -> publication CAS -> Publishing -> bounded genuine terminal write -> finalization remains unchanged. Expired Publishing is unknown, requiring quiescence, not takeover. Late owners cannot save, settle, dispatch or publish after authority loss.
- **I11 — bounded, private recovery:** opaque native/request binding payloads stay private. Read-only lookup performs no model/function work. Return a snapshot only when published SDK 0.8.3 can safely adopt it. Pending mixed approvals with an unresolved registered browser sibling have snapshot-unavailable status, no snapshot and no apparently resumable public batch.
- **I12 — permanent retirement:** expiry/delete/reconcile purge private bytes but retain selector tombstones, consumed decisions, irreversible dispatch metadata and immutable operator audit. Normal maintenance never deletes safety metadata, resets a generation, frees a retired selector for reuse or evicts an unresolved fence.

## Components and trust boundaries

Retain `NativeSessionAgentFactory` as the composition proof and factory; replace its blanket approval rejection only after all protections are composed. Add focused `NativeApprovalContracts.cs`, `NativeApprovalAdmission.cs`, `NativeApprovalAgent.cs`, and `PostgresNativeSessionApprovals.cs`. The admission unit is pure parsing/canonical comparison; the adapter performs only native-content/input/output compatibility; the journal alone reserves and settles durable authority. Existing session/context/projection files own their current responsibilities.

`NativeToolCatalog` must make the registered approval requirement part of its immutable compatibility identity. A server-selected function wrapper determines that requirement; the caller cannot declare or remove it. Keep browser/server names disjoint. Avoid an independent duplicate catalog that can disagree with the factory's functions.

Persist an immutable protected descriptor with: key digest; compatibility/catalog identity; native request ID; original call ID/name/operation version/canonical cloned object arguments; `RequiresConfirmation=true`; original public assistant message ID, call index and content position sufficient for exact reconstruction; server batch ID; published pending revision; DB-clock expiry; descriptor state; decision kind; consuming generation/revision; and eventual genuine result binding. Persist separate native browser bypass descriptors with `RequiresConfirmation=false`, genuine request ID/call/name/args/location and interrupted-batch association. They carry no protected approval or dispatch authority.

Capture original request location deterministically from genuine native output and its resulting public projection. If native output cannot establish one unambiguous supported location, fail representability. Do not guess a location from a caller transcript. Clone JSON/collections at every asynchronous or storage boundary.

Captured-owner provenance is retained for audit, but a later legitimately acquired owner loads and uses the durable descriptor under its own token/generation/revision. Requiring the obsolete capture token to equal the current owner would break cross-instance recovery; accepting a descriptor without current owner CAS would break isolation.

## Public input and pinned native bridge

Admission sees the complete original `RunAgentInput`. Preserve its browser declarations, forwarded configuration, history and raw decisions as the trusted request context. Initial native sessions still reject imported calls/results/approvals. Ordinary native mode keeps the existing strict normalization rules.

For a decision request, parse a separate bounded admission envelope, not a globally relaxed `Normalize`. Normalize the history/configuration without embedding resume responses in the saved canonical prefix; retain validated decisions separately for this request. Only after full journal validation/reservation may the endpoint substitute the upstream transport input. The clone differs only in `Tools=[]`; public metadata, IDs, messages and resume stay otherwise unchanged. The original object is never mutated. Clone `ChatClientAgentRunOptions` and `ChatOptions`, preserving unrelated supported options, and union exactly the admitted original browser declarations with the registered native server catalog ABOVE native invocation. Assert browser JSON schemas are unchanged, each server declaration occurs once and there are no collisions.

Why this is required: pinned AGUI suppresses first-turn protected native interrupts when any client tools are present, and synthesizes unrelated typed Approved=true responses on browser-result continuations. `MapInterrupt` fallback, disabling bypass, or changing outer Contents alone does not repair this behavior. The transport clone avoids both paths; native model options keep the browser tools available. This rule applies to the composed native route, including ordinary mixed-tool continuations, and must preserve milestone-one behavior.

The supported decision wire shapes are exactly:

- `status=resolved`, payload exactly `{approved: boolean}`.
- `status=cancelled`, no payload.

Require bounded IDs and the pinned SDK's actual allowed base fields. Reject unsupported nested fields, caller toolCall descriptors, extra decision metadata, nonboolean approval, null payload for resolved, payload on cancelled and unknown statuses. Unknown harmless top-level protocol fields follow the existing route policy; they cannot enter authority. Cancellation means a decision, not transport abort.

Inside the outer adapter, clone native messages and replace only the stored unresolved original assistant FunctionCallContent at its exact history position with a reconstructed native ToolApprovalRequestContent. Preserve original role/message/call ID, ordering, unrelated contents and allowed metadata. Reconstruct captured nonconfirmation interrupted browser requests in their own same original positions too, retaining `RequiresConfirmation=false`, but never reconstruct settled historical calls. Do not append requests, duplicate histories, manufacture results or inspect private StateBag.

Map each matching generic `InterruptResponseContent` to `original.CreateResponse(true/false)`. Cancellation uses `original.CreateResponse(false, "Cancelled by caller.")`, with the journal retaining the distinct Cancelled disposition. Pinned generic conversion drops raw cancellation status, so only the validated raw admission context determines this kind. Reject unexpected typed approval response contents; no AGUI auto-approved content may become authority. No generic response for these decisions reaches native approval binding.

## Output projection and exact history

Public output is derived outside native invocation; inner native/model history must remain unchanged.

1. Unwrap only captured genuine nonconfirmation browser ToolApprovalRequestContent into its original FunctionCallContent for projection. Keep protected server requests intact so native AGUI emits its genuine interrupt.
2. On an admitted protected resume, suppress only its exact already-public native server call echo: request/call/catalog/name/canonical args and original public location all match current owned admitted evidence. A changed call is an error, never silently hidden.
3. Suppress a second exact echo only for the already-public interrupted browser sibling: native FunctionCallContent has `InformationalOnly=true`, exact stored ID/name/semantic arguments, genuine owned interrupted-batch association, and no accepted browser result. Preserve its genuine rejection FunctionResultContent. Fresh browser calls always remain visible.
4. Clone/synchronize the outer update's native `ChatResponseUpdate` RawRepresentation as well as Contents: pinned `AsChatResponseUpdate` reuses that RawRepresentation. Never mutate the inner native update. Drop a projected update only if it has no representable content; preserve real results/text/unrelated content order.
5. Feed `NativeSessionProjection` explicit request-local owned approval evidence. Seed result correlation for the exact admitted historical protected calls and exact interrupted browser siblings, without another public start/parent. Accept one genuine matching result each. Extend diagnostic validation through that same evidence; do not generally admit `_historicalCallIds` results.

A genuine native interrupt may cancel co-emitted browser siblings in the current published SDK runtime. Its exact SDK annotation is `b4.step={v:1,kind:server,status:cancelled,settledAt:<finite bounded numeric telemetry>}`, even for a correctly registered browser function. The owned prefix comparison may admit only this transition on the exact owned browser sibling associated with the published interrupt and without a result. IDs/name/args/parent/order and every other prefix field remain fixed. Do not infer authority from `kind`, status or timestamp. Timing is untrusted telemetry; expiry always uses the database clock.

On decision resume native binding supplies a real rejection result for the cancelled old browser call. The model can request a fresh browser call with a fresh ID; the SDK executes that fresh call once. Do not promise automatic execution of the cancelled original sibling. Preserve one original call/result pair and one fresh pair thereafter.

The projection accepts an interrupt terminal only if the complete native protected batch and all call bindings match durable capture evidence. Unknown reasons/raw content, malformed batches, unsupported updates, open fragments and exceeded bounds remain unavailable. TurnCompleted is false with either pending approvals or pending browser results. Save cannot acknowledge completion until all protected/bound interrupted call outcomes meet I4 and I9.

## Durable schema version 2 and migration

The existing native schema version 1 is separate from workflow checkpoint schema 3. Initialize fresh databases at native version 2. Upgrade an existing native version 1 under the existing short advisory transaction lock, within one atomic DDL/data-validation transaction. Do not read/rewrite opaque native session JSON to discover approvals.

Add a `native_approvals` table keyed by `(session_id, request_id)` with unique `(session_id, call_id)`, descriptor kind Protected/BrowserBypass, bounded nullable private descriptor, batch ID, Pending/DecisionAdmitted/Settled/Retired state, decision Approved/Declined/Cancelled (protected only), captured generation, admitted generation/revision, expiry and bounded terminal/result digest. Use FK to the native selector. Keep browser-bypass bindings logically distinct with no decision or server invocation grant. An interrupted browser binding may be settled by its native rejection but cannot be accepted as a protected batch member.

Add `native_approval_batches` keyed by `(session_id,batch_id)` to retain immutable batch identity, pending publication revision, member digest/count, Pending/DecisionAdmitted/Settled/Retired state, decision-admitted generation/revision and expiry. Store the exact member descriptors separately; enforce that count/digest agree before publication and admission. This permanent consumed-batch record survives private-byte purge, including zero-dispatch decisions. Session payload version 2 contains explicit protected pending batch and browser bindings or references validated against these rows; it is never the sole consumed fence.

Extend the native invocation state constraint from Captured/Started/Completed to include Declined/Cancelled. Existing Started/Completed columns/rows and their meanings are unchanged. Denial settlement records admitted decision generation and genuine result binding without populating dispatch generation. Approved calls still use exactly the existing Started/Completed path. A call cannot occupy both Completed and a zero-dispatch state.

All genuine version-1 session payloads upgrade with explicit empty approval collections; version 1 could not publish native approvals. Validate existing key/compatibility/payload structure before accepting it as an approval-free upgraded payload. Corruption blocks/unavailable rather than resetting state. Existing Ready/Owned/Saved/Publishing/PublicationUnknown/Blocked/Retired states, generation, revision, lease, invocation markers, selector tombstones and audit rows are preserved. Metadata changes to 2 only after the migration succeeds. Unknown/partial/future native versions fail closed. Migration reruns are idempotent and transaction rollback leaves version 1 untouched. Workflow checkpoint schema-3 bytes and audit remain byte-for-byte unchanged.

Drain version-1 workers and establish quiescence before migration; mixed-version rolling operation is unsupported. New version-2 workers check compatible native metadata during initialization and transactional journal entry points. A stale already-running version-1 binary is not magically stopped by a schema number: deployment exclusion/drain is a prerequisite, documented and tested at its boundary. Never run old and new workers together against upgraded state.

## State transitions, races and failure handling

| Current condition | Action and durable outcome |
| --- | --- |
| Genuine protected request captured | Descriptor Pending; invocation Captured; no dispatch. Save pending native/public batch, authorize and publish genuine interrupt. |
| Complete valid decision against published Pending batch | Acquire current owner and atomically reserve all decisions as DecisionAdmitted before entering MAF. A separate ownership-then-reservation transaction is allowed only if no native work occurs between them and failures before reservation provably leave Pending. |
| Approved native callback | Require matching admitted Approved and current owner; commit Started; call native next at most once; record Completed; persist genuine public result. |
| Declined/Cancelled native result | Require current matching admitted decision; zero executor callbacks; settle invocation Declined/Cancelled and approval Settled with genuine result binding. |
| Invalid decision/prefix/config | No reservation, model call or effect; preserve original pending batch. |
| Failure provably before DecisionAdmitted | Owned cleanup can release untouched Pending if the original save/publication is safe. |
| Failure/abort/crash after DecisionAdmitted, no Started | Retain consumed batch; mark blocked/unknown continuation. Never restore Pending merely because HasDispatch is false. |
| Failure after Started/effect or unknown completion | Retain invocation and consumed-decision fences; no native blob replay or automatic retry. |
| Competing approve/decline or replay | One owner/atomic batch reservation wins; loser conflicts before native/model work; no partial membership consumption. |
| Lost lease/stale late callback | Cancel cooperative work; all later mutations reject token/generation/revision. No late result/cleanup can overwrite current reconciliation. |
| Retirement/expiry | Quiescence requirements remain for publishing/effect ambiguity; atomically purge native/history/argument payloads and preserve minimal selector/decision/call fences and audit. |

Change EVERY existing no-dispatch release/takeover/prune path to account for consumed decisions, not only `FailureCleanupAsync`: expired Owned acquisition, retention maintenance, row retirement, private-byte purge, snapshot validation and call pruning. A generation with any DecisionAdmitted marker is not reusable even when every decision was false. Settled old decisions do not poison a later fully published clean user turn; they remain permanently nonreusable while that current turn's normal ownership rules apply. Tests distinguish failed consumed generation from prior successful settled generations.

Save validates complete genuine rejected-result settlement, consumed generation, descriptor/native/public agreement and no unresolved admitted protected decisions. Successful publication may expose a later new genuine pending batch; the earlier batch remains permanently consumed. Approved siblings are independent dispatch grants after all decisions reserve atomically. Mixed approve/decline/cancel batches therefore have approved effects only.

## Recovery/status and capacity

Keep recovery schema version 1 unless its actual public contract requires a bump; additive optional status reason/pending interrupt fields must be checked against both consumer parsers. Add a precise native approval pending disposition (or map to existing Pending shape without losing meaning), and a bounded `snapshotUnavailableReason` for mixed pending browser calls. A snapshot carries only genuine public interrupts and canonical history plus current server revision; never private descriptors, native blob or saved local batch tokens.

- Native-only pending approval: snapshot may be served after publication, with exact original interrupts and original configuration. restoreConversation adopts a NEW local batch token; lookup/restoration does no model/effect work; explicit decision can continue on another worker after restart.
- Pending mixed approval + unresolved registered browser sibling: return Pending/native pending disposition with reason `PendingMixedBrowserResult` (bounded code), no snapshot and no externally adoptable resumable batch. SDK cancellation annotations cannot complete the browser call. Disable sends/decisions in the unavailable recovery state; expose explicit retirement/new-thread path using existing controls.
- Completed canonical history with real results: existing completed recovery remains eligible. Busy/Blocked/PublicationUnknown/Retired/expired/missing keep their current fail-closed behavior. Stale revision refresh never adopts old approvals.

No omitted call, forged rejection result, tool-registration change or timestamp adjustment may evade the mixed recovery limit. The live current-runtime mixed continuation remains supported; it has not undergone cold restoration.

Use existing MaximumCalls=256 as a combined bound on retained protected+browser approval bindings per selector, not an extra unbounded allowance. Maximum pending protected batch <= MaximumCalls, canonical argument bytes <= ArgumentBytes (64 KiB default), complete private approval descriptor payload <= NativeBytes (1 MiB default) and public request/interrupt projection <= PublicBytes (1 MiB default). Count nested IDs/location/config bytes before parsing/materialization; reject totals before model work. Descriptor storage across tables and payload must not evade the aggregate bound. Approval expiry is no later than session expiry, sampled from DB time. Selector capacity 4096 and payload capacity 128 keep their distinct semantics. Purged minimal fences count against retained selector/call capacity; capacity exhaustion fails before work. Bound queries, audits and stream buffers using existing limits. Do not retain private argument/result text in public status or safety tombstones.

## Remaining risks and explicit limits

Pinned public options/raw representation shapes are experimental; fixture tests must lock them rather than relying on current upstream docs. Pending mixed cold recovery remains unavailable by design. Schema migration requires drained old workers, not mixed-version safety. Native decision admission may consume a batch without an effect; this deliberately sacrifices automatic retry for safety. Native cancellation rejection text is pinned behavior, so journal settlement validates genuine typed/native evidence and its bounded result binding rather than accepting arbitrary caller text. PostgreSQL durability/concurrency and every publication/crash boundary remain unproven until implementation tests pass. Network bytes already authorized/in flight and external effects cannot be retracted by later CAS.
