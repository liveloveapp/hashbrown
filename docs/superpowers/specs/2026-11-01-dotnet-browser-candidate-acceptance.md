# Candidate browser recovery acceptance design

Independently reviewed implementation refinement, 2026-11-01, after Task 6 commit `b47ac193`. This defines the finite legal scenario inventory and evidence requirements. It supplies no executed browser count or qualification claim; those require the actual manifest and results.

Authority: Task 7 of `docs/superpowers/plans/2026-10-31-dotnet-pending-browser-recovery.md`; normative `docs/superpowers/specs/2026-10-31-dotnet-pending-browser-recovery-design.md`, including provider-input and mixed-terminal refinements linked there. Final Task 5 API is `pendingConversationRecovery` plus `resumeConversationRecovery`; React exposes a value and Angular a Signal. Core types are PendingConversationRecovery, BrowserRecoveryOutcome and ResumeConversationRecoveryOptions. Local `pending.id` is the batchId; serverRevision is independent of local recoveryState.revision.

The capability's `serverRevision` is the current Ready session revision returned by the authoritative recovery read. The durable approval batch's `published_revision` belongs to an earlier publication step and may be smaller after finalization or later maintenance. Independently require Ready, the exact current session/capability revision, a positive batch publication revision no greater than that revision, and the genuine batch/member/interrupt joins. Do not equate the two revisions or assume a fixed arithmetic offset. Admitted generation/revision are a third, separately observed lineage.

## Shared real execution/evidence contract

Every successful settlement row uses the following lifecycle, abbreviated `cold` in tables. Open a real candidate page with explicit facade, thread and immutable owned endpoint; initiate generation through that facade's actual start/send/input control. Aimock emits original browser calls, plus genuine protected calls for mixed rows. Browser handler posts an awaited entry observation to a runner-owned HTTP observer, which appends scenario/thread/call correlation and a monotonic sequence BEFORE holding its response on a gate. The observer and append-only record live outside every page and .NET worker. Hold all original handler responses. Wait for independent real journal Ready/publication evidence and record full canonical snapshot/publication revision. Close the original page before releasing its handler gates; unresolved abandoned response promises cannot deliver a browser result into a surviving runtime. Create a fresh page, restoring only thread identity/configuration through actual controls.

Capture local revision before authenticated V2 POST; preserve unchanged getRecoveryConfiguration body and one Hashbrown-Recovery-Version:2 header. Require schemaVersion:2, disposition Pending, positive equal outer/capability serverRevision, exact call IDs and complete genuine interrupts. The page passes expectedRevision to restore. Render names/IDs/arguments as inert text. Observe no `/run` and no observer entries during restore/render/remount. Fill every required known/unavailable outcome and protected decision in actual controls; click submit once. Inspect the browser's unnormalized outgoing request, not a synthesized harness envelope.

Record observer entries before initial page destruction and after restore, settlement, configuration rerender and second reload. Compare original-ID entry sequences: the rerun delta must be zero; the initial count may be nonzero and is never presented as absence of an original effect. A new model-issued ID is distinct and follows ordinary policy. Also require no original-ID observer request was received but left uncounted. For each multi-browser call the initial entry is positively witnessed; observer identity is recorded by trusted fixture call/argument mapping without changing the tool's JSON schema. If the tool handler cannot access callId, give each original browser call a distinct owned argument correlation and map it to the captured canonical callId; do not fabricate an ID in product authority.

For every admitted row independently assert:

- Original stored canonical messages remain byte-equivalent as parsed owned values and keep IDs/order; submitted delta contains exactly one fresh unique tool-message ID per browser call in announcement order and exact toolCallId/content. No user turn, protected result injection, cancellation annotation or historical edits.
- Browser-only resume absent/empty. Mixed resume has every original genuine interrupt exactly once: approve => resolved payload `{approved:true}`, decline => resolved `{approved:false}`, cancel => cancelled with no forged browser ResumeEntry. Controls build ResumeConversationRecoveryOptions using the exact local batchId.
- forwardedProps.hashbrown.recovery version 1 has the captured serverRevision and ordered statuses without values; original browser values are in canonical tool messages only. Normal extensions/schema/UI stay intact.
- Exactly one admitted continuation for that revision; compare journal acquisition/reservation/native preparation observations, raw browser run requests, real provider continuation requests and real append-only PostgreSQL native effects. Successful initial announcement is a separate provider request and must not be counted as a second recovery continuation. Initial mixed publication must have zero protected effects.
- Real serialized Chat messages/tool_call_id or Responses function_call/function_call_output/call_id pairs contain each expected call/result once in correct order. Responses is stateless store:false, no previous_response_id/conversation. Historical completed pairs and unrelated text remain. Inspect actual pre-normalization `fixture.requests` captures through `expectNativeToolPairs` plus explicit prefix/text assertions.
- Native effect rows join the genuine session/call/request/batch/admitted generation+revision. Approve adds one row per approved call; decline/cancel add zero. Never use uniqueness masking as an effect assertion. Per-worker NativeGate counters are summed or differenced for each relevant worker and never treated as durable counters after restart.
- Real saved canonical/opaque/public configuration and actual provider options/wire contain no transient recovery envelope. Next ordinary generation through an actual UI control contains no recovery extension, and does not replay old browser IDs.
- All rejection rows have explicit before/after transport, provider, native preparation, observer and PostgreSQL snapshots; a disabled button alone proves no server/effect behavior.

Known browser string is exact (including whitespace/Unicode); browser object and null use strict JSON serialization (`null` => `null`). Unavailable uses the exact reserved compact marker from the normative spec. The page renders marker/results with normal interpolation; no innerHTML/dangerouslySetInnerHTML.

### Independent native result domains

Each expected native pair has separate fields/witnesses: `originalTypedResult` (when observable), `canonicalPublicContent`, `nativeProjectionValue`, and `providerWireOutput`. They are not interchangeable. An approved protected fixture invocation returns the actual object `{code, name: "Portland International Airport"}` for every owned code; semantic object comparison is appropriate only for the original typed JSON domain. A genuine decline/cancel uses the pinned library's distinct actual result. Obtain those expectations through the real fixture/current protected completion path, not by importing synthetic research fixture constants. Witness the current original typed result at the real native completion boundary and independently compare its outward/canonical projection against the actual saved public tool-content string. Require exact canonical string bytes; do not parse and reserialize away representation differences.

For already completed ordinary history, the retained typed AGUI result may itself be the canonical public content STRING (including a JSON-encoded server string), rather than the original handler-return value. Apply the actual SerializeForNativeResult/projection policy and then the pinned provider SDK wire codec independently: expected provider output is not universally the handler string, nor a universal JSON.stringify of every result. Record the expected intermediate type and final exact Chat/Responses output per historical call and per current call. Exact canonical prefix equality and ordinary adjacent native pairs are separate assertions; pair order must not be inferred from the original public message layout. Real actual serialized wire remains the final independent witness. Browser result domains retain the exact browser rules above.

### Concrete public transport deadline

HttpTransportOptions has no timeout setting. The timeout row uses a candidate-owned, hash-qualified wrapper implementing the public Transport interface around the real public HttpTransport. Its send method receives the actual TransportRequest, starts an owned finite deadline, composes a new AbortController with request.signal (including already-aborted state/reason), and delegates a shallow request wrapper with the SAME `request.input` object identity. Never clone/rebuild request.input: the private one-attempt WeakSet is keyed by that identity and must remain effective. Preserve requestId/attempt/maxAttempts and all original fields; change only signal. Do not add an SDK API or access the WeakSet privately.

Keep the deadline and original-signal listener alive while consuming the returned real events iterator; clear timer/listener on completion/error/dispose, forwarding delegate disposal. A timer cleared when send returns would fail to test a stalled SSE body. The owned proxy forwards the real immutable request, records server admission/bytes, and holds the delivered response so the finite browser deadline actually fires. Record monotonic deadline creation/firing and abort reason, upstream/page byte boundaries, resulting facade recovery-required state, and failed same-token resubmission. No Playwright test timeout, assertion polling timeout or proxy-only dropped socket is accepted as timeout evidence. The actual facade stop/cancel row remains a separate original-signal cancellation case; focused positive/negative tests must prove either signal propagates and wrapper cannot trigger a second attempt.
