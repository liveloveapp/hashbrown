# Canonical streaming, schemas and decisions lessons

Continue the approved canonical two-step plan and four visible LLA panels. Preserve
light surfaces, compact bottom milestones, immutable synchronized replay, retained
conversations and contextual Details/Raw/Console. No visual redesign.

Streaming and schemas use the existing real structured-chat clients. Streaming
marks the title as a streaming string and steps as a streaming array, making raw
chunks and SDK-resolved previews observable. Schemas starts in a Schema inspector
showing the exact shared response contract and keeps application validation and
successful completion distinct from schema types. Both continue the existing
prompt, explicit Accept plan, revision and shorter-follow-up sequence.

Decisions uses actual useDecision/decisionResource and the real TypeSafe adapter,
with server-only credentials and pinned jev-1.14.0 model during recording. The app
owns a fixed two-step plan: outline trusted UI, then record the demo. The first
request says the outline is complete; the closed choice is record, review, or
clarify. The second says the demo is recorded; the choice is review. Decisions
return a complete typed value and confidence, never streamed generated text or
props. A fresh successful choice at confidence >=0.75 enables Use suggestion;
this explicit action saves nextAction and advances revision. Low confidence,
errors, cancellation and stale responses leave state unchanged and offer manual
review guidance. Each request has a fresh SDK runtime/nonce so old values cannot
be mistaken for a new result. No automatic request or write on lesson selection.

Decision requests/responses, typed outcomes, confidence, explicit selection and
application snapshots join the same trace and timeline. Replay renders inert
captured decision cards and never calls the model or applies a choice. UI/plan
capture extraction remains format-specific and unchanged. Server endpoints are
allowlisted and pin schemas, system policy and question options; browser input is
bounded, credentials stay server-side, abort/timeouts/concurrency remain enforced.
