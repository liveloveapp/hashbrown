## Configuration and authentication

AzureAuthentication accepts exactly api-key, azure-cli or managed-identity, default api-key. Unknown or explicit empty values fail at startup. OpenAI accepts only api-key. Require a nonempty ApiKey only for API-key mode. Token modes succeed with no ApiKey and never fall back, even when a key exists and selected identity fails.

Azure CLI uses AzureCliCredential with ProcessTimeout ten seconds, using the existing authorized CLI account; never interactive login, global account changes or subscription repair. Do not add tenant/subscription selectors absent demonstrated need. Managed identity uses the non-obsolete ManagedIdentityCredential(ManagedIdentityId.SystemAssigned); trusted ManagedIdentityClientId selects ManagedIdentityId.FromUserAssignedClientId. Reject explicitly empty IDs or selector use outside managed-identity mode. No workload/developer credential chain.

Provider, API, model/deployment, endpoint, mode, identity selector and scopes remain server-owned. Browser forwarding cannot change them. Token endpoints must be absolute HTTPS, without user-info/query/fragment; reject HTTP before token acquisition or dispatch. API-key localhost HTTP fixtures remain valid. Preserve Azure root normalization to /openai/v1/. Trusted public-cloud scopes: Responses https://ai.azure.com/.default; legacy Azure cognitive-services audience https://cognitiveservices.azure.com/.default. Never derive scope from arbitrary caller endpoints/challenges. Both scopes require actual Azure preflight before qualification is claimed.

Preserve ServerConfigurationIdentity v1 inputs (API, provider, canonical effective endpoint, model); mode, credentials and identity selector stay excluded. Rotation/key-to-Entra changes retain checkpoint compatibility, routing/model/API changes invalidate it.

Keep ProviderFactory.Create(IConfiguration) as the recipe-facing entry point. Add only the smallest immutable composition seam for test credentials and SDK transports, exercised by native Probe.csproj/cs.txt subprocesses; no browser-configurable fake-token/TLS hooks. Responses uses BearerTokenPolicy with the selected TokenCredential, OpenAIClient, zero retries, existing StatelessResponsesClient/AsIChatClient. Legacy uses AzureOpenAIClient's TokenCredential overload, zero retries. Credential owns caching; never capture startup token text in ApiKeyCredential.

CLI execution is bounded by its ten-second ProcessTimeout; live Responses qualification exercises actual acquisition cancellation. Runner deadlines also terminate owned fixture processes, so they do not depend on legacy refresh completing. Do not claim legacy credential work is caller-cancelled.

## Budgets and secrets

Enforce before dispatch: one worker, zero native/Playwright retries, <=4 calls per scenario, <=128 calls total, <=384 requested output tokens per call, <=60 seconds per scenario, <=15 minutes overall. Forty-two scenarios at four calls each would exceed 128: implement a scenario manifest with exact expected upper bounds before dispatch. Initial allocation 1+1+2+2+2+3+3=14 calls/project (84), plus <=3 preflights, leaves bounded contingency. Refine to actual actions; every continuation/cancel/failure counts, and unused allowances never increase a scenario beyond four. Token-cap incompletion fails. No automatic rerun on failure.

Reserve immutable per-project ceilings before execution: 14 × 6 plus at most three preflights is at most 87 calls; no global budget broker is needed when each native fixture enforces its scenario cap. Link scenario/run deadlines to credential acquisition and the native iterator, recheck immediately before each native dispatch, and abort/terminate owned children on deadline. A Playwright timeout or dispatch-time clock check alone is insufficient for in-flight work. Gate opt-in/config validity before constructing dispatch-capable processes. Load only the authorized env file when live execution begins; never during design. Allowlist child variables; CLI also receives only necessary OS execution environment and existing CLI profile location. Do not print/read profile contents, dump inherited environment, pass secrets in arguments, put provider keys in browser configs/URLs/bundles, or enable raw cloud captures.

Allowlisted diagnostics: provider/API/auth/model, sanitized path/status, duration/usage, safe stage/effect/budget counters. Redact secret values, authorization/api-key and identity tokens before any persistence sink, including child stdout/stderr and exception handling. No raw exception bodies, response bodies or retained Playwright traces by default. Bound diagnostics to 2 MiB/run; tests inject canary secrets and fail on any persisted occurrence.
