# Pending Browser Cold Recovery Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Explicitly settle every durably witnessed pending browser call, together with all genuine protected-native decisions, after inert restoration and continue under journal revision CAS without rerunning original browser handlers.

**Architecture:** Negotiate a V2 recovery read and opt into an additive journal capability that validates immutable original raw evidence and complete append-only canonical settlement under a transaction. Preserve canonical public history while pairing only current witnessed calls on an independent public typed native clone immediately before FICC. Core owns a separate inert pending epoch and one-shot settlement claim; every React/Angular restoration facade forwards that public contract, with persistent uncertainty derived from canonical results.

**Tech Stack:** Existing TypeScript/AG-UI core, React, Angular signals, Nx/Jest/Vitest/Playwright; .NET 10, pinned public MAF 1.26.0, OpenAI 2.14.0, Microsoft.Extensions.AI.OpenAI 10.10.1, existing Npgsql/PostgreSQL 18. No new dependencies or live model requests.

## Test evidence convention

Tasks are sequential reviewable work packages, not five-minute completion promises. Within each package the implementer works one named scenario, one failing assertion, one RED run, one focused production change, and one GREEN run at a time (roughly 2–5 minutes per edit/inspection action; integration runs can take longer). Do not write an entire layer before behavioral tests. Every task starts with a named failing behavior assertion using real production entry points or public consumer contracts. A missing type compile error can be a useful initial public API RED, but cannot replace behavior RED. Root runs each named command once after the new test is written, records expected failure, then repeats after minimal implementation and requires success. Existing failures/environment blocks are distinguished from the intended regression. No planned count below is an assertion that tests already pass. “No replay” always concerns the ORIGINAL recovered call IDs and their handlers. Add explicit tests rejecting reuse of an original settled ID while allowing a genuinely fresh model-issued call ID after admitted continuation under normal tool policy. Unavailable results do not promise semantic deduplication: applications must authorize or idempotently guard newly requested side effects; implement no unsolicited duplicate-execution subsystem.

A journal recovery-method invocation is an admission attempt, not successful ownership acquisition. Malformed protocol syntax rejects before that attempt. Conflicts that require stored evidence may enter the capability method and must reject transactionally before any lease, session preparation, provider or executor authority. Keep those counters distinct; do not add a pre-read merely to hide the authoritative validation attempt.

For any added `.NET tests/*.spec.ts`, explicitly add it to `tools/conformance/dotnet/test-suites.ts` runtime/harness/package ownership and matching `project.json` inputs; its guard rejects missing/duplicate specs. Extend lint/prettier source lists for new harness/config files because `conformance:lint` explicitly ignores the dotnet subtree. Shared `.cs` fixture probes use the established `createDotnetProbeDirectory`, compile against actual production project, and assert observable output. They may use existing passive observation hooks but do not grant authority or substitute counter assertions for real boundaries.
