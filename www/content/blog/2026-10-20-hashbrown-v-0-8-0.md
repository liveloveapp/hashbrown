Today we are releasing Hashbrown v0.8.

The headline is decisions.
Until now, Hashbrown only talked to generative models: you send a prompt, text and UI stream back.
In v0.8, Hashbrown also talks to decision models, which answer a closed question about your app state with a typed value and a confidence, in about a hundred milliseconds.
The first adapter is [TypeSafe](https://docs.typesafe.ai)'s Jev.

The rest of the release finishes the move to AG-UI 1.0 that v0.7 started.
There is one breaking change, and it lands on the server: Hashbrown's run-input extension now travels in AG-UI's `forwardedProps`.
Your React components and Angular resources don't change.

**Release at a glance**

- `useDecision()` and `decisionResource()`: typed answers from a decision model, with confidence, on a vendor-neutral decision protocol.
- `useUiDecision()` and `uiDecisionResource()`: let a decision pick which components to show.
- `@hashbrownai/typesafe`, a server-only adapter for TypeSafe's Jev.
- The run-input extension moves into `forwardedProps.hashbrown`, AG-UI's extension point.
- `lastRunResult`, the run's return value, on every chat and completion API.
- A cancelled run settles cleanly instead of raising an error.
- `markdownComponent()`, so a server can pin the full UI response schema.
- A v0.8 migration guide for React and Angular, with a prompt for your AI coding assistant.

## Decide or Generate

Some questions in an app have an open-ended answer.
Write a summary.
Explain this chart.
Fill in the props of a card.
That's generation, and it's what Hashbrown has always done.

Other questions have an answer from a known set.
Which panel should this query open?
Is this message a complaint?
On a scale of minus two to two, how urgent is this?
Streaming text at those questions is slow, expensive and hard to parse.
A decision model answers them directly, as a typed value with a probability attached, and it does it fast enough to run on every keystroke.

In v0.8, you ask one with a Skillet schema.
`s.enumeration()` gains per-option descriptions, so the model knows what each option means:

<hb-code-example header="route a question">

```tsx
import { s } from '@hashbrownai/core';
import { useDecision } from '@hashbrownai/react';

const routeSchema = s.object('Where to send the question', {
  intent: s.enumeration('What the user wants to do', {
    filter: 'Narrow the list of flights on the map',
    chat: 'Ask a question that needs a written answer',
    other: 'Anything else',
  }),
  clear: s.boolean('The user wants to clear the current filter'),
});

function Search({ query }: { query: string }) {
  const route = useDecision({
    schema: routeSchema,
    input: query === '' ? null : query,
    system: 'You route questions in a flight-tracking app.',
    debounceTime: 150,
  });

  if (route.value?.intent === 'filter') {
    return <FilterPanel />;
  }

  return <Chat />;
}
```

</hb-code-example>

In Angular, `decisionResource()` takes the same schema and returns signals:

<hb-code-example header="search.component.ts">

```ts
readonly route = decisionResource({
  schema: routeSchema,
  input: computed(() => (this.query() === '' ? null : this.query())),
  system: 'You route questions in a flight-tracking app.',
  debounce: 150,
});
```

</hb-code-example>

`value` is typed from the schema.
`meta` carries the model's confidence in the same shape, so you can route on it: act when the model is sure, and fall back to a generation when it isn't.

A `DecidableSchema` is checked at compile time, so the schema can only ask what a decision model can answer: enumerations, booleans, bounded numbers and objects of those.
Decisions never stream and never write text.

### Let a decision pick your UI

The place this shines is generative UI.
`useUiDecision()` and `uiDecisionResource()` work in two modes.
In candidates mode, your code builds every option and the model picks which ones to show.
In narrowing mode, the decision picks components from your kit and the existing UI completion streams their props, from a kit narrowed to the chosen components.
If the model is unsure, or the decision fails, it falls back to the full kit.

The [UI Selection recipe](/docs/react/recipes/ui-selection) walks through both.

### TypeSafe's Jev on the server

Decisions run on a server route that holds your key, `/api/decide` by default.
`@hashbrownai/typesafe` maps Hashbrown's decision protocol to Jev's API with `fetch`, so it adds no dependencies:

<hb-code-example header="server.ts">

```ts
import { HashbrownTypeSafe } from '@hashbrownai/typesafe';

app.post('/api/decide', async (req, res) => {
  const decision = await HashbrownTypeSafe.decide({
    apiKey: process.env.TYPESAFE_API_KEY!,
    model: 'jev-1.14.0',
    request: req.body,
  });
  res.json(decision);
});
```

</hb-code-example>

It validates the client's request before any network call, retries rate limits, and reports failures as a `DecisionError` with a typed code.
Pass `schema` to pin the questions on the server, the same way you pin a prompt.
Pin the model version too; there is no `jev-latest`.

The protocol is plain JSON and vendor-neutral, so other decision models can follow.
Read [Decisions](/docs/react/concept/decisions) for the concept and the [TypeSafe platform page](/docs/react/platform/typesafe) for the server.

## What Do I Need to Change?

Hashbrown sends a standard AG-UI run input, plus an object of its own: the response schema for structured output and a flag for generative UI.
Since v0.6, that object rode along as a top-level `hashbrown` key.
AG-UI 1.0 has a proper home for it: `forwardedProps`, the field an agent reads and intermediaries pass through untouched.
A proxy or gateway that validates the input strictly could drop a key it doesn't know; it can never drop `forwardedProps`.

In v0.8, the extension travels there, and only there:

<hb-code-example header="before">

```ts
const responseSchema = input.hashbrown?.responseSchema;
```

</hb-code-example>

<hb-code-example header="after">

```ts
const responseSchema = input.forwardedProps?.hashbrown?.responseSchema;
```

</hb-code-example>

If you use an official adapter and never read the extension yourself, update the client and the server adapter together and you're done:

<hb-code-example header="terminal">

```sh
npm install @hashbrownai/core@0.8.0 @hashbrownai/react@0.8.0
npm install @hashbrownai/openai@0.8.0
```

</hb-code-example>

Swap `react` for `angular`, and `openai` for your provider.
A v0.8 client sends only the new shape, so an adapter still on v0.7 would see no schema and answer in free text.
Upgrade both sides in the same deploy.

If your server reads the extension itself, to pin the schema or to pick a model, make the one change above.
The [v0.8 guide for React](/docs/react/migrations/v0-8) and [for Angular](/docs/angular/migrations/v0-8) covers it, and ends with a prompt you can hand to an AI coding assistant like Claude Code.

## The Run's Return Value

An AG-UI agent can attach a return value to the event that ends a run, separate from the messages and from shared state.
A LangGraph graph returns its final state.
A workflow returns a summary record.
A judge returns a verdict.
Hashbrown used to drop it.

In v0.8, it's `lastRunResult`:

<hb-code-example header="react">

```tsx
const chat = useChat({ system, transport });

const verdict = chat.lastRunResult;
```

</hb-code-example>

<hb-code-example header="angular">

```ts
readonly chat = chatResource({ system, transport });

readonly verdict = computed(() => this.chat.lastRunResult());
```

</hb-code-example>

It's the return value of the last run that completed, as any JSON value, or `undefined` when the agent attached none.
It's cleared when the next run starts, so a value always belongs to the messages on screen.
Interrupted, cancelled and failed runs never set it.
It's on `useChat`, `useCompletion`, the structured and UI hooks, and every Angular chat and completion resource.

Hashbrown's own provider adapters don't produce one.
Use it with an agent you run yourself.

## Cancelled Runs

AG-UI 1.0 lets a server end a run with `outcome: { type: 'cancelled' }`: the run was stopped before it completed, and it did not fail.
Hashbrown read that as a malformed interrupt and raised an error.

In v0.8, a cancelled run settles like a local stop.
The partial answer is rolled back, nothing is retried, and `error` stays empty.
The next message on the thread starts an ordinary new run.

## Pin the Whole UI Schema on the Server

In v0.7, `createUiJsonSchema()` let an agent Hashbrown doesn't run build the UI schema your kit sends.
One piece was missing: the Markdown component's definition lived only inside the React and Angular packages, so a server couldn't rebuild a schema that included it.

In v0.8, `markdownComponent()` lives in core:

<hb-code-example header="run-handler.ts">

```ts
import { createUiJsonSchema, markdownComponent } from '@hashbrownai/core';

const PINNED_RESPONSE_SCHEMA = createUiJsonSchema({
  components: [
    markdownComponent(),
    { ...flightCardContract, children: false },
    { ...arrivalsBoardContract, children: false },
  ],
});
```

</hb-code-example>

That closes the loop on a public endpoint.
The browser builds the request, but anyone can send any request to your endpoint with `curl`.
A server can now pin the system prompt, the tools and the full UI schema, replacing whatever the browser sent and logging a warning when it differs.
The new [Securing a Public Endpoint](/docs/react/recipes/public-endpoint) recipe uses the server of [atc](https://github.com/liveloveapp/hashbrown/tree/main/examples/atc), our example app, as the worked example, down to request caps, rate limiting and a budget cap.

## Conclusion

Decisions give Hashbrown a second kind of model: fast, typed, and built for routing and selection.
The run-input extension now sits where AG-UI 1.0 wants it, `lastRunResult` surfaces what your agent returns, cancelled runs settle cleanly, and a server can pin everything the model sees.

The migration guides for [React](/docs/react/migrations/v0-8) and [Angular](/docs/angular/migrations/v0-8) cover the one change, step by step.

Have questions? Hit a snag while upgrading? [Open an issue on GitHub](https://github.com/liveloveapp/hashbrown/issues) and let me know!
