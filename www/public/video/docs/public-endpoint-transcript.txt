Check access before starting a reply

This recording probes the actual checked Express application's /api/chat route. The browser uses a locally issued fixture session, an in-memory server repository, and scripted provider events. There is no deployed identity service or real model call. Presentation styles and a branded frame are added by the recorder. No narration.

1. The result preview shows an authorized streamed reply.
2. Check the endpoint without a session. The actual response is HTTP 401; no provider stream starts.
3. Start a local demo session. The fixture issues an opaque HttpOnly, SameSite cookie.
4. Request another owner's private thread. The actual response is HTTP 404.
5. Request the authorized Personal thread. The endpoint verifies identity, Origin, ownership, bounded text input, and admission before invoking the provider fixture.
6. The browser displays the actual streamed event types and text: Hi Sam, welcome to Hashbrown!

The production adapter replaces fixture identity, repository, and admission implementations with application integrations and selects provider credentials, model, and output cap on the server. The local login fixture is recording infrastructure, not a production authentication implementation.
